# 开发与维护

本项目不引用 Forge 项目的绝对路径，不依赖开发工具或开发会话常驻。构建入口是根目录 build.py，测试入口是 test.py。

## 模块

| 代码 | 负责的工作 |
| --- | --- |
| FabricAccess、FabricMixinPlugin | 版本限制、映射与字节码接口探测，生成本项目自己的 Mixin 标记类 |
| HookWeaver、FabricHooks | 向已确认的回调和窗口/资源方法插入观察入口，异常不替换原始 Mod 异常 |
| TaskRegistry、LoadingProgress | 当前回调、完成数、单一总进度与完成条件 |
| FabricController、CompletionGate | 启动、资源完成、原加载覆盖层退出后的帧交接、统一关闭 |
| NativeHandle、NativeAttachment、Win32Ops | 识别 GLFW/SDL，检查同进程窗口，挂接和恢复窗口样式 |
| FabricSurface、YuvFrame | 有界像素缓冲、CPU YUV 转换、视频和 UI 合成 |
| core/MediaSession、AudioClock | FFmpeg 管道、音频时钟、循环播放、退出清理 |
| core/Settings、Theme、PackName | 外部配置、文字样式与整合包名称 |

core 中部分源文件基于既有 MIT 代码，来源文件和摘要在 upstream-media.json，许可保留在 THIRD-PARTY-LICENSES。Fabric 专有代码和后续新增部分按本项目 LICENSE 执行。

## 兼容策略

先限制已知正式版本范围，再检查实际游戏类、方法签名和本地窗口调用。GLFW/SDL 通过 Window 字节码中的调用判断，不通过“类路径是否存在某个库”猜测。

旧版使用 Fabric 的 intermediary 映射解析接口；26.3 使用实际游戏字节码检查资源接口和 Gui.setOverlay 交接位置。未知布局直接退出动画接入。

本项目使用标准 Mixin 插件，同时涉及 Fabric Loader 内部的字节码读取和 classpath 扩展接口。它们不是跨未来版本的稳定 API，因此更新 Loader 后必须重新检查，不能只扩大版本号范围。

默认语言适配器中能定位的直接回调才加入任务观察。对自定义语言、继承回调和工厂入口另做适配前，应先确认能准确对应到模组，不能猜测当前加载条目。

生成的 Mixin 标记 Jar 只含本项目生成的类，写入 fabric_loading/cache。文件名使用内容 SHA-256，同一内容复用，已有文件摘要不符时拒绝加载。不会修改磁盘上的 Minecraft、Fabric Loader 或 PCL。

## 自动检查

build.py 使用独立输出目录，避免旧 class 混入 Jar；依赖下载后按锁定摘要检查。

test.py 的检查分三类：独立逻辑和异常路径；实际新旧 Mixin 引擎；已有官方游戏文件的字节码接口。--ffmpeg 会生成一秒钟的测试视频，检查循环解码、有界队列和关闭后的子进程退出，不创建窗口或打开音频设备。

这些检查不能代替 PCL 启动验证。发布正式版前仍需在副本中观察动画、音频、窗口交接、渐隐和进入主菜单，检查低配置设备实际耗时。检查记录默认留在 audit，分发时不附带。

## 发布

Fabric 保持独立仓库和发行包，不与 Forge Jar 混装。正式发行包应包含本项目 Jar、配置模板、教程和所需运行文件的许可；源码包排除 Minecraft、账户、日志和机器相关路径。
